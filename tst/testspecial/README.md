These tests are designed to check GAP's output in the break loop.

Most of the cleverness is in `./run_gap.sh`, where we make sure we capture
all of GAP's output, stop GAP attaching to the terminal, and rewrite any
filenames which occur in output.

`./run_gap.sh` : This runs GAP, capturing its input/output
`./run_all.sh` : This runs all the tests
`./regenerate_tests.sh` : Regenerate all outputs

A test whose first line is `#GAPOPTS <options>` is run with these additional
GAP command line options.

## The `window-cmd*.g` tests

These test how `WindowCmd` reads the answer of a window handler in package
mode (`gap -p`). `WindowCmd` sends its command to stdout and reads the answer
from stdin, and GAP does not read ahead on stdin, so a test puts the answer
on the line after the call:

    got := WindowCmd(["TST"]);;
    @a8+I0+S2+ok

The kernel does not interpret the command name `TST`. The newline after an
answer is read by GAP as an empty line.

An answer is `@a<len>+<entries>`, where `<len>` is the number of bytes of
`<entries>`. An entry is an integer `I<digits><sign>` or a string
`S<len>+<bytes>`. All numbers are written least significant digit first, so
`52` means 25. In `<entries>` a `@` is written as `@@` and a control
character as `@A` to `@Z`; the `<len>` of a string counts un-escaped bytes.
The first entry is a status which `WindowCmd` removes; if it is 1, the other
entries become the arguments of `Error`.

The tests are generated by `dev/make-window-cmd-tests.g`.
